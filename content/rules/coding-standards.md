# Стандарты разработки

Применять вместе с локальным стилем изменяемого модуля.

## Форматирование

- Сохранять форматирование и регионы существующего модуля; не переформатировать несвязанный код.
- Один оператор размещать на строке. Длинное выражение переносить по смысловым частям, сохраняя читаемую вложенность.
- Многострочные строки продолжаются `|` и пробелами; текстовые `\t`, `\n`, `\r` не являются BSL escape-последовательностями.
- Не выравнивать большие блоки пробелами так, чтобы изменение одного имени требовало переформатирования соседних строк.
- Во всём содержимом `.bsl`, включая идентификаторы, комментарии и строковые литералы, не использовать `ё/Ё` (U+0451/U+0401); заменять на `е/Е`. В пользовательской документации вне `.bsl` эти буквы допустимы.
- Не использовать длинное тире `—` (U+2014) в `.bsl`; использовать дефис `-` (U+002D). Примеры BSL в правилах также оформлять с учётом этих ограничений.

## Имена и API

- Не использовать магические строки и числа, если у значения есть устойчивый предметный смысл.
- Имя временной переменной должно отражать содержимое или этап алгоритма.
- Не менять сигнатуру, тип результата или наблюдаемое поведение экспортного метода без проверки вызывающих.
- Публичный метод имеет не более семи параметров. При превышении порога передавать структуру параметров.

### Поиск существующей реализации

Перед написанием нового кода, в том числе вспомогательного метода (#std440):

1. Проверить, нет ли готовой экспортной реализации в релевантных общих и менеджерских модулях, по `.opencode/rules/source-search.md`. Не дублировать подходящую реализацию; предварительно проверить её контракт и контекст выполнения.
2. Проверить библиотеки проекта. Для БСП загрузить skill `bsp`, сверить API с версией проекта и проверить как минимум `ОбщегоНазначения`, `ОбщегоНазначенияКлиентСервер`, `СтроковыеФункцииКлиентСервер`.
3. Создавать новый универсальный метод только при наличии минимум двух реальных вызовов в текущей задаче. Иначе оставлять метод локальным.

## Методы и условия

- Процедура или функция решает одну задачу. Предусловия проверять в начале ранним выходом, если это не скрывает основную ветку.
- Максимальная вложенность условий и циклов — три уровня. При превышении выносить самостоятельную часть в отдельный метод.
- Параметры располагать от обязательных к необязательным. Не использовать длинный набор булевых параметров вместо структуры настроек или нескольких предметных методов.
- Не сравнивать булево значение с `Истина` или `Ложь`, если прямое условие читается однозначно.
- Избегать отрицательных условий и «йода»-сравнений, если они ухудшают предметное чтение кода.
- Не использовать тернарный оператор для ветвей с побочными эффектами или сложной логикой.

## Клиент и сервер

- Клиент не выполняет запросы и тяжёлую обработку данных; минимизировать клиент-серверные переходы и размер передаваемых значений.
- Не обходить в цикле строки или элементы любых коллекций в клиентском контексте (`&НаКлиенте`). Обработку коллекций выполнять на сервере.
- `&НаСервереБезКонтекста` предпочтительнее, если данные формы не нужны. Не применять директиву механически: используемые методы и значения должны быть доступны в выбранном контексте.
- Не размещать бизнес-логику записи и проведения в форме.
- Не использовать `Сообщить()`. Для сообщений пользователю использовать `ОбщегоНазначения.СообщитьПользователю(...)` на сервере и `ОбщегоНазначенияКлиент.СообщитьПользователю(...)` на клиенте. Наличие, сигнатуры и доступность API подтвердить через skill `bsp` и источники версии проекта; если нужный метод недоступен, согласовать альтернативу, а не возвращаться к `Сообщить()`.

### Асинхронность
- Не использовать модальные окна и синхронные диалоги (`Вопрос`, `Предупреждение`, `ВвестиЗначение` и аналоги). Выбирать асинхронный вариант, доступный на минимальной платформе и при режиме совместимости проекта.
- Перед использованием `Асинх`/`Ждать` проверить поддержку платформой и клиентом: платформа 8.3.18+. Если поддержки нет, использовать `ОписаниеОповещения`: экспортную клиентскую процедуру с параметрами операции. Для обычного результата диалога — `(Результат, ДополнительныеПараметры)`; для остальных оповещений сигнатуру проверять отдельно.
- Обработчик формы с `Асинх` не приостанавливает завершение платформенного события сам по себе. Не использовать его там, где платформа должна дождаться решения до закрытия, записи или отмены действия, без подтверждённого шаблона этого события.

Примеры
```bsl
// Пример ОписаниеОповещения
&НаКлиенте
Процедура ОчиститьТовары(Команда)
    Оповещение = Новый ОписаниеОповещения("ОчиститьТоварыЗавершение", ЭтотОбъект);
    ПоказатьВопрос(Оповещение, "Очистить все товары?", РежимДиалогаВопрос.ДаНет);
КонецПроцедуры

&НаКлиенте
Процедура ОчиститьТоварыЗавершение(Результат, ДополнительныеПараметры) Экспорт
    Если Результат <> КодВозвратаДиалога.Да Тогда
        Возврат;
    КонецЕсли;
    Объект.Товары.Очистить();
КонецПроцедуры

// Пример Асинх/Ждать
&НаКлиенте
Асинх Процедура ЗагрузитьФайл(Команда)
    Результат = Ждать ПоместитьФайлНаСерверАсинх(,,,, УникальныйИдентификатор);
    Если Результат = Неопределено Тогда
        Возврат;
    КонецЕсли;
    ОбработатьФайлНаСервере(Результат.Адрес);
КонецПроцедуры

&НаСервереБезКонтекста
Процедура ОбработатьФайлНаСервере(АдресФайла)
    Данные = ПолучитьИзВременногоХранилища(АдресФайла);
    // Обработка полученных двоичных данных.
КонецПроцедуры
```

## Данные, запросы и производительность

- Значения передавать в запрос через `Запрос.УстановитьПараметр(...)`, не конкатенацией строк. Имена реквизитов и табличных частей сверять с метаданными; оформление, псевдонимы и проектирование запроса — по `query-design.md`.
- Не читать реквизиты ссылок через точку: `Контрагент.ИНН` загружает объект целиком и создаёт скрытые обращения к БД. Для одного реквизита на сервере использовать `ОбщегоНазначения.ЗначениеРеквизитаОбъекта(Контрагент, "ИНН")`, подтвердив API версии БСП проекта. Запрет относится к разыменованию ссылок в BSL, а не к полям запросов или свойствам уже полученных объектов и структур.
- Результат `Запрос.Выполнить()` всегда сохранять в отдельную переменную: `РезультатЗапроса = Запрос.Выполнить();`. Затем вызывать `РезультатЗапроса.Выбрать()` или `РезультатЗапроса.Выгрузить()`; цепочки `.Выполнить().Выбрать()` и `.Выполнить().Выгрузить()` запрещены.
- Для коллекции выбирать алгоритм по объёму и частоте поиска: повторный линейный поиск внутри цикла заменять соответствием, индексом либо пакетной выборкой.
- Кэшировать только данные с понятным временем жизни и способом инвалидирования.
- Не получать объект целиком ради чтения одного-двух реквизитов (#std496). Несколько реквизитов читать одним запросом. В проекте на БСП использовать `ОбщегоНазначения.ЗначенияРеквизитовОбъектов(...)`, предварительно проверив наличие метода в версии БСП проекта.
- В рамках одной операции набор записей в один регистр записывать один раз, а не построчно в цикле (#std792).

```bsl
// Плохо: скрытый запрос к базе на каждой итерации.
Для Каждого Строка Из Объект.Товары Цикл
	Вес = Строка.Номенклатура.Вес;
КонецЦикла;

// Хорошо: один запрос на все ссылки.
Запрос = Новый Запрос(
"ВЫБРАТЬ
|	Номенклатура.Ссылка КАК Ссылка,
|	Номенклатура.Вес КАК Вес
|ИЗ
|	Справочник.Номенклатура КАК Номенклатура
|ГДЕ
|	Номенклатура.Ссылка В(&Ссылки)");
Запрос.УстановитьПараметр("Ссылки", Объект.Товары.ВыгрузитьКолонку("Номенклатура"));

Веса = Новый Соответствие;
РезультатЗапроса = Запрос.Выполнить();
Выборка = РезультатЗапроса.Выбрать();
Пока Выборка.Следующий() Цикл
	Веса.Вставить(Выборка.Ссылка, Выборка.Вес);
КонецЦикла;
```

## Обработчики записи и обмен

В обработчиках `ПередЗаписью`, `ПриЗаписи`, `ПередУдалением` и в подписках на эти события сначала проверять `ОбменДанными.Загрузка` (#std773, #std464, #std465, #std752). При обмене объект должен загружаться как есть, без дополнительных проверок и действий.

```bsl
Процедура ПередЗаписью(Отказ)

	Если ОбменДанными.Загрузка Тогда
		Возврат;
	КонецЕсли;

	// Код обработчика.

КонецПроцедуры
```

Исключение — обмен, который при загрузке регистрирует изменения для выгрузки на другие узлы плана обмена. Любое другое исключение пояснять комментарием. Код, устанавливающий `ОбменДанными.Загрузка = Истина`, сам отвечает за заполнение и целостность объекта. Проверка BSL LS: `DataExchangeLoading`.

## События и фоновые операции

### **Что запрещено в обработчике записи и проведения.**
Диалоги с пользователем, обращения к внешним системам, долгие вычисления. Фактическую транзакционную границу события и правила конкурентности проверять по `transactions.md`.

### **Фоновое и регламентное задание** (#std540, #std539, #std642).
В проектах на БСП: фон запускай через подсистему длительных операций (`ДлительныеОперации.ВыполнитьВФоне`), регламентные задания описывай средствами подсистемы регламентных заданий. Обязательно в коде задания:
  - Единица работы: порция из N объектов с обоснованным размером; границы записи и блокировки — по `.opencode/rules/transactions.md`.
  - Обработанное помечается (реквизит или регистр), при перезапуске задание продолжает с необработанных.
  - Параллельный запуск того же задания исключён или безопасен (проверка активного задания, блокировка).
  - Ошибки и прогресс пишутся в журнал регистрации с уровнем.
  - Отмена: проверка признака отмены между порциями.

## Транзакционный путь

При изменении записи, проведения, ответственного чтения, блокировок или фоновой обработки загрузить `.opencode/rules/transactions.md` по профильному маршруту. Это единственный владелец правил транзакций и конкурентности.

## Расширения

Перед перехватом метода проверить в исходниках точной версии основной конфигурации:

1. Метод существует с таким именем.
2. Контекст `&НаСервере`, `&НаКлиенте` или `&НаСервереБезКонтекста` совпадает с оригиналом.
3. Количество и порядок параметров совпадают с оригиналом.

Сигнатуру и тело перехватываемого метода сверять с точной версией основной конфигурации. После обновления типовой конфигурации повторно сверять `&ИзменениеИКонтроль` с оригинальным телом.

- `&Перед` и `&После` не меняют контракт метода.
- Результат функции изменять через `&Вместо`, вызывая `ПродолжитьВызов(...)`, если контракт требует исходную логику.
- `&ИзменениеИКонтроль` применять только для вставки в середину метода: такое изменение наиболее чувствительно к обновлениям.
- Для всех новых имён использовать префикс расширения. Заимствовать только необходимые объекты и формы. Исключение для имён тестов расширения `tests` определяется профильным правилом YAxUnit из `AGENTS.md`.

## Надёжность и безопасность

- Привилегированный режим минимален по области и обоснован. Не использовать его для обхода неверно спроектированных прав.
- `УстановитьПривилегированныйРежим(Истина)` в модуле формы запрещён (#std485). Привилегированную операцию размещать в серверном модуле и ограничивать минимальным фрагментом; учитывать восстановление режима при исключении и права получателя результата.
- Не включать пароли, токены, персональные данные и содержимое закрытых документов в код, URL и диагностические сообщения.
- `Выполнить` и `Вычислить` с внешними или пользовательскими данными запрещены (#std770, #std801, #std669). Если динамический код неизбежен, перед его вызовом включать безопасный режим и обосновывать решение в итоговом отчёте.
- Экспортный серверный метод, доступный с клиента, не доверяет входным данным: самостоятельно проверяет права и валидирует параметры (#std678, #std679). Признак `Вызов сервера` общего модуля устанавливать только при реальной необходимости.
- При анализе или изменении проверки прав загрузить `access-rights.md`: выбор между правом на объект и ролью-маркером, совокупность ролей и доступ к конкретным данным при RLS определяются там.
- Данные из внешнего, динамического или слаботипизированного источника проверять и нормализовать на границе. Внутри прикладного метода работать с одним согласованным представлением, а не повторять проверки типа в каждой ветви.
- Перед чтением необязательного свойства структуры проверять его наличие либо использовать согласованный безопасный accessor; отсутствие свойства и пустое значение не смешивать.

## Исключения
- Перехват исключения без записи в журнал и без повторного броска запрещён (#std499). 
- Пользователю показывать `ТекстОшибки = ОбработкаОшибок.КраткоеПредставлениеОшибки(ИнформацияОбОшибке())`, 
- В журнал записывать `ТекстОшибки = ОбработкаОшибок.ПодробноеПредставлениеОшибки(ИнформацияОбОшибке())`. 
- Не перехватывать исключения без необходимости. Необработанное исключение автоматически выводится пользователю и сохраняется в журнал регистрации. 
- Если при возникновении исключения дальнейшая работа должна быть остановлена. Перехваченное исключение дополняем дополнительной информацией и прокидываем выше. Пример:
```
    ИнформацияОбОшибке = ИнформацияОбОшибке();
    ТекстСообщения = ОбработкаОшибок.СообщениеОбОшибкеДляПользователя(ИнформацияОбОшибке);
    ТекстСообщения = НСтр("ru = 'Не удалось загрузить файл классификатора АУЦ:'")
        + Символы.ПС + ТекстСообщения
        + Символы.ПС + НСтр("ru = 'Возможные причины:
        | • Нет подключения к Интернету;
        | • На веб-узле возникли неполадки;
        | • Брандмауэр или другое промежуточное ПО (антивирусы и т.п.) блокируют попытки программы подключиться к Интернету;
        | • Подключение к Интернету выполняется через прокси-сервер, но его параметры не заданы в программе.'");

    ДляАдминистратора = ДиагностикаСоединенияСИнтернет();
    ВызватьИсключение(ТекстСообщения, , , ДляАдминистратора, ИнформацияОбОшибке);
```


## Локализация

- Пользовательские строки оборачивать в `НСтр` (#std761, #std764, #std763).
- Подстановки выполнять через `СтрШаблон(НСтр("ru = '... %1'"), Значение)`, а не конкатенацией.
- Форматирование даты, числа и булева значения задавать явно через `Формат`.

## Журналирование

- Писать в журнал для диагностируемого эксплуатационного события, ошибки или явно поставленной задачи, а не как замену обработке результата.
- Категория события стабильна, именуется в формате `Метаданные.Операция` и оформляется через `НСтр` (#std498); уровень важности соответствует влиянию, а не удобству поиска.
- Диагностический контекст содержит идентификатор операции, безопасные ключи объекта, этап и номер попытки, но не сериализованный объект целиком.
- При обработке исключения сохранять исходную причину и добавлять контекст текущей операции. Не создавать несколько одинаковых записей на каждом уровне вызова.
- Не журналировать секреты, персональные данные и большие тела запросов/ответов. Не писать запись на каждую строку массовой операции без отдельной диагностической необходимости.

```
Попытка
    ЗаписьЖурналаРегистрации(НСтр("ru = 'Мой механизм.Действие с возможной ошибкой'", КодОсновногоЯзыка),
        УровеньЖурналаРегистрации.Информация, , ,
        НСтр("ru = 'Начато действие'"));

    ДействиеСВозможнойОшибкой(ОбъектДействия);
```

## Комментарии и сопровождение

- Комментарий объясняет причину, ограничение, неочевидный алгоритм или контракт, а не пересказывает строку кода.
- Комментарий публичного метода не должен обещать поведение, которого нет в реализации.
- `TODO` и `FIXME` содержат ссылку на задачу либо достаточное условие удаления временного решения.
- Не оставлять закомментированный код, временные сообщения, точки останова и неиспользуемые переменные, созданные текущей правкой.
