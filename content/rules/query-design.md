# Запросы 1С

Перед написанием определить требуемые строки, группировку, период и поведение при пустых данных. Выбрать источник по предметному смыслу: неправильная таблица или виртуальная таблица — ошибка проектирования, а не задача оптимизации. Таблицы, точные имена реквизитов и табличных частей и типы полей сверить с метаданными, загрузив skill `meta-info`; для запроса внутри СКД дополнительно загрузить skill `skd-info`. Не угадывать имена по синонимам или похожим объектам.

## Базовые правила

- Выбирать только используемые поля; свёртку, сортировку и простые вычисления выполнять в запросе. Не усложнять запрос ради переноса всей постобработки в СУБД: несколько простых вариантов могут быть стабильнее одного универсального (#std729).
- Значения всегда передавать параметрами через `Запрос.УстановитьПараметр(...)`; подстановка значений конкатенацией строк запрещена. Для СКД и динамических списков использовать их механизм установки параметров, не встраивать значения в текст запроса.
- Текст запроса оформлять многострочно, ключевые слова писать заглавными. Каждому полю выборки и источнику всегда задавать явный понятный псевдоним через `КАК`, даже если имя не меняется: `Контрагенты.ИНН КАК ИНН`.
- Результат `Запрос.Выполнить()` всегда сохранять в промежуточную переменную. Не цеплять к выполнению `.Выгрузить()`, `.Выбрать()` или другие методы результата:

```bsl
РезультатЗапроса = Запрос.Выполнить();
ТаблицаРезультата = РезультатЗапроса.Выгрузить();
```

- `ОБЪЕДИНИТЬ ВСЕ` использовать вместо `ОБЪЕДИНИТЬ`, если удаление дублей не требуется. Не применять `РАЗЛИЧНЫЕ` для маскировки ошибочного соединения.
- Учитывать `NULL`, составные типы и добавляемые RLS соединения. Если нужен ограниченный результат, ограничивать выборку в запросе.
- Не добавлять `РАЗРЕШЕННЫЕ` как универсальное исправление ошибки доступа (#std415): конструкция исключает недоступные данные и может исказить результат. Не использовать её в запросах, влияющих на расчёты и проведение; обеспечить необходимый доступ либо прервать операцию при его недостатке. Для списков и отчётов выборка только доступных данных допустима, если такая неполнота соответствует предметному контракту, включая смысл итогов. При анализе или изменении прав/RLS загрузить `access-rights.md`.

Однотипные данные получать одним запросом через `В`, пакет или `ОБЪЕДИНИТЬ ВСЕ`. Запрос в цикле допустим только когда он нужен для порционной обработки, обращений к виртуальной таблице на разные даты либо подтверждённо быстрее и проще общего запроса (#std436).

Для `В (&Массив)` учитывать длину списка и ограничения СУБД/платформы: при более 1000 элементов рассмотреть типизированную временную таблицу и соединение. Это ориентир для проверки плана, а не универсальный жёсткий порог. Удалять лишние дубли, сохранять семантику пустого списка.

## Форматирование текста запроса

- Текст оформлять как многострочную строку BSL. Первое `ВЫБРАТЬ` — на строке после присваивания `Запрос.Текст =`, последующие строки начинаются с `|`. Отступ BSL перед `|` соответствует вложенности кода; отступ после `|` задаёт структуру запроса.
- Основные секции (`ВЫБРАТЬ`, `ПОМЕСТИТЬ`, `ИЗ`, `ГДЕ`, `СГРУППИРОВАТЬ ПО`, `ИМЕЮЩИЕ`, `УПОРЯДОЧИТЬ ПО`, `ИНДЕКСИРОВАТЬ ПО`, `ИТОГИ`) начинать с новой строки на одном уровне. Имя временной таблицы писать рядом с `ПОМЕСТИТЬ`.
- Каждое поле выборки, группировки, сортировки или индекса размещать на отдельной строке с одним уровнем отступа. Запятую ставить в конце строки; не собирать список полей в одну длинную строку.
- Источник после `ИЗ` — с одним уровнем отступа. Соединение — на уровень глубже источника; `ПО` — на уровне соединения, продолжения его условий — ещё на уровень глубже. Условия после `ГДЕ` — с одним уровнем отступа. Каждое дополнительное условие `И`/`ИЛИ` начинать с новой строки, логический оператор ставить в начале строки. Группы условий заключать в скобки, вложенные продолжения сдвигать ещё на уровень.
- `ВЫБОР`, его ветви и `КОНЕЦ`, а также длинные выражения переносить по смысловым частям с отступами по вложенности. Не выравнивать псевдонимы пробелами в колонку.
- В новом коде использовать единый шаг отступа (в примерах — четыре пробела); в существующем модуле сохранять принятый вид отступов. Между запросами пакета ставить `;` и пустую строку (`|` в строке BSL); `ОБЪЕДИНИТЬ ВСЕ` выделять отдельной строкой между выборками.

Образец оформления соединения, условий и группировки (таблицы и поля должны быть подтверждены в проекте):

```bsl
Запрос.Текст =
"ВЫБРАТЬ
|   Товары.Номенклатура КАК Номенклатура,
|   ЕСТЬNULL(Остатки.Количество, 0) КАК Остаток,
|   СУММА(Товары.Количество) КАК Количество
|ИЗ
|   ВТ_Товары КАК Товары
|       ЛЕВОЕ СОЕДИНЕНИЕ ВТ_Остатки КАК Остатки
|       ПО Товары.Номенклатура = Остатки.Номенклатура
|           И Товары.Склад = Остатки.Склад
|ГДЕ
|   Товары.Количество > 0
|   И Товары.Склад = &Склад
|СГРУППИРОВАТЬ ПО
|   Товары.Номенклатура,
|   ЕСТЬNULL(Остатки.Количество, 0)";
```

## Запрос по таблице значений

Таблицу значений сначала поместить во временную таблицу. Колонки передаваемой таблицы значений должны иметь определённые типы.
```bsl
Запрос.Текст =
"ВЫБРАТЬ
|    ТЗ.Номенклатура КАК Номенклатура,
|    ТЗ.Количество КАК Количество
|ПОМЕСТИТЬ ВТ_Данные
|ИЗ
|    &ТаблицаЗначений КАК ТЗ
|;
|
|ВЫБРАТЬ
|    ВТ_Данные.Номенклатура КАК Номенклатура
|ИЗ
|    ВТ_Данные КАК ВТ_Данные
|ГДЕ
|    ВТ_Данные.Количество > 0";
```

## Условия и индексы

- В основном условии не применять функции, арифметику, отрицание и `<>` к индексируемому полю. Диапазон допустим по последнему используемому полю индекса.
- `ИЛИ` в основном условии допустимо для одного поля, когда выражение эквивалентно `В`. Условия `Поле1 = ... ИЛИ Поле2 = ...` при необходимости разделять через `ОБЪЕДИНИТЬ ВСЕ`, только если это не меняет строки и дубли.

```bsl
// Плохо: функция мешает поиску по индексу даты.
ГДЕ МЕСЯЦ(Документы.Дата) = &Месяц

// Хорошо.
ГДЕ Документы.Дата МЕЖДУ &НачалоПериода И &КонецПериода
```

Добавление индекса или изменение порядка измерений согласовать с пользователем: индекс ускоряет чтение, но замедляет запись и может ухудшить другие запросы.

## Виртуальные таблицы

- Условия по виртуальной таблице передавать в её параметр условия, соединяя предикаты через `И`. Перенос из `ГДЕ` допустим только при сохранении смысла среза, остатков или оборотов: ранний фильтр может изменить результат (#std657).
- В параметре условия использовать простые предикаты по полям самой таблицы. Сложные выборки с разыменованием через точку, соединениями, RLS или подзапросами предварительно получать во временную таблицу. Переносить выборку, а не отключать ограничения RLS; сохранять область доступа и смысл результата.
- `СрезПервых` и `СрезПоследних` применять только к периодическим регистрам сведений; периодичность подтвердить по метаданным.
- Производные поля (`*Остаток`, `*Оборот`, `*Приход`, `*Расход`) не угадывать: подтвердить ресурс и вид виртуальной таблицы по метаданным или проверенному запросу.

```bsl
// Плохо: после расчета всей виртуальной таблицы.
РегистрНакопления.Товары.Остатки() КАК Остатки
ГДЕ Остатки.Склад = &Склад

// Хорошо: условие участвует в расчете виртуальной таблицы.
РегистрНакопления.Товары.Остатки(, Склад = &Склад) КАК Остатки
```

Для текущих остатков самый эффективный вариант возможен, когда дата не задана, разделение итогов выключено, а все измерения виртуальной таблицы участвуют во внешнем `ВЫБРАТЬ` или `ПО` (#std733). Применять это только когда предметный смысл действительно требует текущих остатков.

## Соединения и временные таблицы

- Не соединять напрямую с вложенным запросом и не помещать подзапрос в условие `ПО`. Результат вычисления сначала помещать в именованную временную таблицу, затем соединять с ней (#std655, #std656).
- Вложенные соединения не заменять последовательными механически: они могут возвращать разные строки. Если последовательное соединение не сохраняет смысл, использовать временную таблицу.
- Соединение с виртуальной таблицей работает медленно, выборку из виртуальной таблицы помещать во временную таблицу, затем выполнять соединение уже с временной таблицей
- Во временную таблицу помещать только нужные строки и поля (#std777).
- Большую временную таблицу индексировать по полям `ПО` или по полям справа от `В (...)`. Маленькую таблицу до примерно тысячи строк автоматически не индексировать. При неизвестном объёме сначала запросить оценку у пользователя.
- Сложный пакет запросов разбивать на методы по смысловым этапам: подготовка исходных данных, расчёт показателей, получение результата. Один метод может формировать несколько связанных временных таблиц, решающих одну задачу. Границу метода определяет назначение этапа, а не количество таблиц; правило «один метод = одна временная таблица» не применять.
- Все связанные запросы выполнять с одним общим экземпляром `МенеджерВременныхТаблиц`, передавая его в методы и назначая свойству `Запрос.МенеджерВременныхТаблиц`.
- В контракте каждого этапа указывать используемые и создаваемые временные таблицы и необходимые параметры. Вызывающий метод задаёт порядок этапов по зависимостям. Не создавать новый менеджер внутри этапа и не уничтожать таблицы, нужные следующим этапам.

### Пример смысловой декомпозиции

Схема вызывающего метода (предметные методы реализуются под задачу):

```bsl
МенеджерВТ = Новый МенеджерВременныхТаблиц;
// Создает ВТ_Строки и ВТ_Потребность - единый этап подготовки потребности.
ПодготовитьПотребность(МенеджерВТ, ТаблицаТоваров);
// Использует ВТ_Потребность, создает ВТ_Остатки и ВТ_Обеспечение.
РассчитатьОбеспечение(МенеджерВТ, Склад);
// Читает ВТ_Обеспечение и возвращает итоговую выборку.
Результат = ПолучитьРезультатОбеспечения(МенеджерВТ);
```

Первый этап может выполнять один пакет с двумя связанными временными таблицами:

```bsl
// Создает ВТ_Строки и ВТ_Потребность; входных временных таблиц нет.
// ТаблицаТоваров содержит типизированные колонки Номенклатура и Количество.
Процедура ПодготовитьПотребность(МенеджерВТ, ТаблицаТоваров)

    Запрос = Новый Запрос;
    Запрос.МенеджерВременныхТаблиц = МенеджерВТ;
    Запрос.УстановитьПараметр("ТаблицаТоваров", ТаблицаТоваров);
    Запрос.Текст =
    "ВЫБРАТЬ
    |    Товары.Номенклатура КАК Номенклатура,
    |    Товары.Количество КАК Количество
    |ПОМЕСТИТЬ ВТ_Строки
    |ИЗ
    |    &ТаблицаТоваров КАК Товары
    |;
    |
    |ВЫБРАТЬ
    |    Строки.Номенклатура КАК Номенклатура,
    |    СУММА(Строки.Количество) КАК Количество
    |ПОМЕСТИТЬ ВТ_Потребность
    |ИЗ
    |    ВТ_Строки КАК Строки
    |СГРУППИРОВАТЬ ПО
    |    Строки.Номенклатура";
    Запрос.ВыполнитьПакет();

КонецПроцедуры
```

## Проверка оптимизации

Проверить N+1 через точку, коррелированные подзапросы, подзапросы в `ВЫБРАТЬ`, поздний фильтр виртуальной таблицы и условия, мешающие индексу. Пять-семь таблиц считать сигналом проверить сложность и план выполнения, а не жёстким лимитом (#std729).
